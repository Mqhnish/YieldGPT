The problem

Company knowledge lives on four platforms, each with its own permission rules

C /

Confluence

  • Space permissions
  • Page restrictions
  • Inherited from parent pages
J /

Jira

  • Project roles
  • Issue security levels
  • Inside one project
# /

Slack

  • Public and private channels
  • Direct messages
  • Several workspaces
△ /

Drive

  • Shared and personal drives
  • Folder inheritance
  • Link and external shares

An assistant that copies everything into one index can show people what they were never allowed to open, and nobody can prove afterwards who saw what.

What YieldGPT does

Ask once. Get a cited answer built only from sources you may open right now.

01

Plain-language question

Across all four platforms at once, routed by a planner to the right sources and time window.

02

Each platform decides

Every source is checked live with Confluence, Jira, Slack or Drive itself, as that person. No copied access lists.

03

Everything on the record

The question, every allow or deny, what the model saw and what was released: hash-chained and checkpointed.

Architecture

Four trust boundaries, one direction of trust

Write-once checkpoints
Confluence · Jira · Slack · Drive
YieldGPT server
Language model
  • UntrustedThe language model. Its output is a proposal, never a decision.
  • TrustedThe YieldGPT server runs every check and writes the audit.
  • Source of truthThe platforms themselves decide every permission.
  • IndependentWrite-once checkpoint stores the app cannot rewrite.
The model

The language model is treated as untrusted.

  • It only ever sees passages that already passed checks A to C.
  • It holds no credentials and calls no tools.
  • Unsupported claims are dropped; citations may only point at sources it was given.
  • Injected instructions in a question are blocked; poisoned passages are quarantined.
In this submission answers are extractive: assembled on the server from authorized passages, word for word, each line cited. The model adapter is optional.
Audit and compliance

Every answer is on the record before it leaves

Hash-chained log

Each row hashes the one before. Edits, deletions, truncation and a full recompute are all detected. Question and answer text is encrypted at rest.

No checkpoint, no answer

The answer is held until its audit rows are checkpointed. If checkpointing fails, the user gets a refusal, never an unrecorded answer.

Two write-once anchors

S3 Object Lock in compliance mode, written to two stores. A forged anchor disagrees with the other and verification fails.
